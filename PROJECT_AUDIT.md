## 1. ОБЩЕЕ ОПИСАНИЕ И СТЕК

### 1.1 Назначение

**PWA-навигатор по территории ГБУЗ «Инфекционная больница №2»** — офлайн-совместимое веб-приложение для посетителей больницы. Позволяет:

- выбрать точку старта (сканированием QR-кода на входе в корпус или вручную из списка);
- выбрать целевое отделение/корпус на карте;
- построить кратчайший маршрут по графу дорожек и вывести его поверх растрового плана территории;
- работать без интернета после первого визита (Service Worker + кэш).

### 1.2 Стек технологий

| Технология | Роль |
|---|---|
| **Pure Vanilla JS (ES5-стиль, `var`, без сборщиков и фреймворков)** | Вся логика: `map.js`, `ui.js` |
| **HTML5** | Разметка: `index.html` |
| **CSS3** | Стили и адаптив: `styles.css` |
| **SVG (инлайн)** | Маркер старта, иконки, линия маршрута (`<path>` с маской и анимацией) |
| **Raster image (`webp`)** | Растровый план территории: `hospital-map.webp` (2016×864 px, ~1 МБ) |
| **Service Worker** | Кэширование и офлайн-режим: `sw.js` |
| **Web App Manifest** | Метаданные PWA: `manifest.json` |
| **html5-qrcode (CDN)** | Единственная внешняя зависимость — сканер QR-кодов из welcome-модалки |
| **Google Fonts (CDN)** | Шрифт Inter |

Сторонние **картографические библиотеки не используются** — см. п. 4.1.

### 1.3 Деплой и точка входа

- Точка входа: **`index.html`** (корень репозитория).
- Хостинг: **GitHub Pages** (remote `https://github.com/StepAce/Hospital_Map.git`, проект деплоится с корня ветки по умолчанию).
- Все ресурсы подключены **относительными путями** (`styles.css`, `map.js`, `data.json`, `hospital-map.webp`), что необходимо для корректной работы на подпути GitHub Pages.
- Приложение регистрирует Service Worker из `sw.js` (scope — корень проекта).

## 3. МОДЕЛЬ ДАННЫХ И НАВИГАЦИЯ

### 3.1 Структура `data.json` (текущая схема)

```
data.json
├── config
│   ├── mapWidth        (2016), mapHeight (864) — номинальные размеры плана
│   ├── metersPerPixel  (0.25) — масштаб для GPS-перевода координат
│   └── mapImage        ("hospital-map.webp")
├── startPoints         ([]) — ПУСТОЙ массив; заполняется автоматически (см. 3.3)
├── waypoints           ([W1..W43]) — глобальные узлы дорожек: { id, x, y }
├── graph.edges         ([{from, to}, ...]) — рёбра между узлами графа
└── buildings           ([10 зданий])
    └── departments     ([1..6 отделений в здании])
        ├── id, name (может содержать \n — перенос вывески)
        ├── x, y       — координаты точки (двери/входа)
        ├── label_x, label_y — позиция текстовой плашки (вывески)
        └── entryW     — привязка ко входу на граф дорог:
                         строка ("W19") или массив (КПП: ["W1","W42"])
```

**Здания (id → роль):** 1 — Главный корпус; 2 — воздушно-капельная инфекция; 3 — кишечная инфекция; 4 — социальные койки; 5 — гепатит; 6 — Диагностический корпус; 7 — КТ-диагностика; 8 — Патолого-анатомический; 9 — Пищеблок; 10 — КПП.

**Стартовые точки (QR) и их смысл** (справочник в `_comment_guide` файла):
- `qr_101` Приёмное отделение … `qr_106` 2-е отделение;
- `qr_201` 5-е отделение; `qr_301`/`qr_302` 6-е/7-е; `qr_401` 3-е; `qr_501`/`qr_502` 4-е/8-е;
- `qr_601`–`qr_604` КДО/БАК/КДЛ/Рентген; `qr_701` КТ; `qr_801` Пат-анат; `qr_901` Пищеблок; `qr_1001` КПП.
- Алиасы в коде: `qr_gate` → `qr_1001` (КПП), `qr_admin` → `qr_102` (Администрация) — см. `setStartPoint()` в map.js.

### 3.2 Логика графа путей

**Узлы** (коллекция `allNodes`, ключи-префиксы):
- `W*` — waypoints дорожек (`isWaypoint`);
- `B<id>` — корпуса (`isBuilding`);
- `D<id>` — отделения (`isDept`, привязка к корпусу через `buildingId`);
- `qr_*` — стартовые точки (`isStart`);
- `_from`/`_to` — виртуальные узлы при маршрутизации от произвольных координат.

**Построение (`buildGraph`)**:
1. Узлы корпусов, стартовых точек, отделений + waypoints.
2. Рёбра: соседние waypoints внутри `dept.waypoints` (в текущих данных не используется, waypoints глобальные); последний waypoint → узел отделения.
3. Рёбра из `appData.graph.edges` — два формата поддерживаются: массивы `["A","B"]` и объекты `{from,to}`.
4. **Авто-привязка стартовых точек:** если у `qr_*` задан `entryW` — ребро к этим waypoints; иначе — к ближайшему waypoint (метод «nearest»).

**Поиск пути (`findPath`)** — классическая **Дейкстра** по матрице расстояний (O(V²)), рёбра неориентированные, вес = евклидово расстояние. При недостижимости цели возвращает `null` с `console.warn`.

**Маршрутизация от/до отделений (`findPathSnapped`)** — ближайшие waypoints для старта и цели, поиск пути, добавление виртуальных узлов `_from`/`_to` (без рёбер, только для отрисовки линии).

**Отрисовка маршрута (`drawRouteLine`)** — SVG `<path>` поверх `#markersLayer`:
- сглаживание кривыми Безье (`ROUTE_LINE_CONFIG.curveTension = 0.3`);
- пунктир `8 6`, цвет `#E53935`, ширина 4;
- анимация «прорастания» маской (~1 c, `easeInOutQuad`), далее — бесконечный бегущий пунктир через класс `route-running` (флаг `ANIMATE_ROUTE_INFINITE = true`);
- при перестройке панели — пересчёт `updateRoutePathData` и полная перерисовка.

### 3.3 Обработка входящих параметров URL

Точки входа для QR-переходов: `?start=`, `?qr=`, `?node=` (приоритет именно в этом порядке).

| Значение | Действие |
|---|---|
| `?start=qr_1001` (или любой `qr_*`) | `setStartPoint('start', id)` |
| `?start=D<id>` (напр. `D102`) | `setStartPoint('dept', 102)` |
| `?start=B<id>` | `setStartPoint('building', id)` |

Особенности:
- Параметры разбираются в `handleQRParam()` (map.js) **до** `buildGraph()` — порядок критичен, т.к. `addEdge` требует готовые `allNodes`.
- Если URL-параметров нет — старт принудительно ставится на КПП (`qr_1001`), затем применяется сохранённый `localStorage.savedStartPoint`.
- QR-сканер в welcome-модалке (`onScanSuccess` в ui.js) умеет принимать как **голый id** (`qr_101`), так и **полный URL** с параметром (`...?start=qr_101`) — извлекается `start|qr|node`.
- При `?start=` welcome-модалка не показывается (условие `if (!params.get('start')) showModal()`).

## 4. ТЕКУЩИЙ СТАТУС, РИСКИ И ЗАПРЕТЫ

### 4.1 Запреты (архитектурные ограничения)

- **ЗАПРЕЩЕНО подключать внешние картографические библиотеки** (Leaflet, Google Maps API, Mapbox и т.п.). Весь рендеринг — только нативный DOM/SVG/CSS. Причины: офлайн-режим (внешние tile-серверы недоступны без сети) и экономия веса.
- **ЗАПРЕЩЕНО менять схему данных** без обновления `map.js`: поддерживаются и объектные, и массиво-форматы рёбер, `entryW` строкой/массивом, отделения строкой/объектом — но новые поля координат должны быть согласованы с рендером.
- Исходный код (JS/CSS/HTML/JSON) не должен модифицироваться при аудите/документировании — только чтение.

### 4.2 Правила инвалидации кэша Service Worker при релизах

- Версия кэша живёт в `sw.js` как `CACHE_NAME = 'hospital-nav-v1001'`.
- **Правило релиза:** при любом изменении `map.js`, `ui.js`, `styles.css`, `index.html`, `data.json`, изображений или иконок — **обязательно инкрементировать версию** в `CACHE_NAME` (например → `v1002`). Комментарий первой строки `sw.js` описывает, что изменилось в этой версии.
- Механизм обновления: новый SW устанавливается с новым кэшем → `skipWaiting()` → `activate` удаляет все кэши, кроме текущего (`caches.keys().filter(key !== CACHE_NAME)`) → `clients.claim()`. На клиенте `updatefound`/`controllerchange` (map.js) выполняют `window.location.reload()` — приложение само перезагрузится на свежую версию.
- `data.json` дополнительно запрашивается с кэш-бастером `?v=Date.now()`, фолбэк — чистый `fetch('data.json')` (кэш SW). `caches.match(..., { ignoreSearch: true })` гарантирует отдачу закэшированного файла.
- `loadData()` при недоступности данных и `!navigator.onLine` показывает офлайн-заглушку `#offlineNotice`.

### 4.3 Известные особенности / риски

- **GPS-модуль дремлющий:** `computeGeoTransform()` читает `data.json.geoRef`, но поле **отсутствует** в текущем `data.json` → перевод широты/долготы в пиксели не работает; `requestGPS()`/`findNearestLocation()` не имеют опорных данных.
- **`btnChangeStart`/`btnResetStart` не существуют в разметке** — ветки кода для смены/сброса старта в `main()` и `updateHint()` фактически неактивны (вызовы защищены `if (btnChange && btnReset)`).
- **Загрузка графики:** `hospital-map.webp` (~1 МБ) — основной вес страницы; критичен для первого офлайн-захода.
- **Внешние CDN:** html5-qrcode и Google Fonts недоступны офлайн. QR-код сканируется только при интернете; шрифт Inter фолбэчится на системный `sans-serif`.
- **`data.json.bak`** — устаревшая копия схемы (waypoints внутри отделений, явный `startPoints`), в приложении не используется; служит резервом для отката.
- **Единый id для SVG-маски** `#routeMask` — при одновременных маршрутах возможны конфликты; в текущем сценарии один маршрут за раз.
- **Welcome-модалка:** при `?start=` не показывается; после скана — скрытие с анимацией 300 мс и установка точки через `setTimeout`.

### 4.4 Ближайшие запланированные улучшения

1. **Привязка плашек (вывесок отделений) по углам** — авто-расстановка `label_x`/`label_y` с учётом границ карты и соседних плашек, чтобы вывески не вылезали за край плана.
2. **Карточки bottom-sheet** — замена/дополнение списка корпусов и hint-панели выдвижными карточками целевого отделения (название, корпус, этаж, действия «Построить маршрут»/«Отменить»).
3. (Предполагается по коду) дозаполнение `geoRef` для включения GPS-навигации и появление контролов смены/сброса стартовой точки.
